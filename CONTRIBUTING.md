# Contributing to Lotr Renewed Extended

Thank you for your interest in contributing to **Lotr Renewed Extended** for Minecraft 1.16.5! Whether you are fixing bugs, adding new features, translating, or improving assets, we appreciate your help in bringing Middle-earth to life.

---

## Licensing & Contribution Rules

Before contributing, please note our **Dual-License Model**:
* **Source Code & Data:** Licensed under **LGPL-3.0-or-later**. You can freely fork and contribute code, recipes, advancements, and text.
* **Visual & Audio Assets:** **All Rights Reserved (ARR)**. You cannot submit copyrighted artwork or audio ripped from other projects.

### Mandatory CLA Signing on Your First PR
To protect the project, **all contributors must sign our Contributor License Agreement (CLA)**. 
* When you open your **very first Pull Request**, our automated bot (`CLA Assistant`) will leave a comment with instructions on how to sign the CLA. 
* Once signed, your PR will be automatically unlocked for review. You will **not** need to sign it again for future pull requests.

---

## ## Contribution Acceptance & Large Changes
Please note that not every contribution or pull request is guaranteed to be accepted. To ensure your work aligns with the vision of the mod and to save yourself time and effort, please consult the team before starting work on large additions, major gameplay changes, or new features.
* **Before you code**: Open an issue or start a discussion on GitHub to pitch your idea and get feedback from the maintainers.
* **Scope matters**: Bug fixes, small tweaks, translations, and minor asset improvements generally do not require prior consultation, but massive overhauls or brand-new feature additions do.

## Prerequisites & Requirements

Before setting up your workspace, ensure you have the following installed:
* **Java Development Kit (JDK):** Ensure you have the correct Java version installed (Minecraft 1.16.5 Forge environments typically require **Java 8**).
* **Git** or **GitHub Desktop** for cloning and managing the repository.

To download the repository via your terminal, run:
```bash
git clone https://github.com/LotrExtendedTeam/LotrRenewedExtended.git
cd LotrRenewedExtended
```

---

## Forking & Branching Strategy

We do **not** accept pull requests directly into the `main` branch. All pull requests, bug fixes, and feature additions must be submitted against our **`development`** branch.

### How to Fork and Branch:
1. **Fork the repository:** Click the **Fork** button at the top right of the main repository page on GitHub to create a copy under your own account.
2. **Clone your fork** locally using the git clone command mentioned above, but with the correct url for your forked repository.
3. **Create a feature branch:** Before making any changes, switch to the development branch and create a new working branch:
   ```bash
   git checkout development
   git checkout -b feature/your-feature-name
   ```
4. **Push and Pull Request:** Once your changes and data generations are complete and tested, push your branch to your fork and open a Pull Request targeting our **`development`** branch.

## Setting Up Your Development Environment

1. Download or clone your fork of this repository (`LotrRenewedExtended`) using Git or GitHub Desktop.
2. Open the project root folder in your preferred IDE.

### IntelliJ IDEA
* Open the project directory.
* Configure the project using the Gradle side menu in the IDE, **or** run the following in your terminal:
  ```bash
  ./gradlew genintellijruns
  ```
  Then, click the **"Reload all Gradle projects"** button in IntelliJ.

### Eclipse
1. Run the workspace generation command:
   ```bash
   ./gradlew eclipse genEclipseRuns
   ```
2. If you experience issues with Eclipse, try clearing and cleaning the configuration completely:
   * `./gradlew cleanEclipse clean` (to clean the configuration)
3. Rebuild the Eclipse configuration and run files:
   ```bash
   ./gradlew eclipse genEclipseRuns
   ```
4. Importing into Eclipse: Go to File > Open Projects from File System..., select your repository folder, and finish importing.
5. If none of the above resolve your configuration issues, delete your local workspace environment and re-clone the repository from the remote origin.

## Running Data Generation

If you are adding or modifying blocks, items, recipes, or loot tables, you will need to run data generation to automatically output all corresponding JSON files.

You can execute data generation via your terminal:
```bash
./gradlew runData
```

Alternatively, you can run data generation directly from your IDE using the pre-configured run configurations generated by ForgeGradle:
* **IntelliJ IDEA:** Open the run configurations dropdown at the top right of the window, select the data generation run configuration (typically named something like `runData`), and click the **Run** button.
* **Eclipse:** Open your Debug/Run Configurations, look under Java Application (or Gradle tasks depending on your setup), select the `runData` configuration, and click **Run**.

## Building the Mod

To compile your code and build a distributable `.jar` file of the mod, run the following Gradle task:

```bash
./gradlew build
```

Once the build is successful, you can locate the final compiled JAR file inside the **`build/libs/`** directory.
